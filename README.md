# GodManagerBot v2.0

## Мониторинг Telegram-чатов

Сервис `chatmonitor` читает новые сообщения от лица пользовательской Telethon-сессии
`botAccount.session`, ищет ключевые слова и отправляет найденные сообщения через
Bot API-бота в личную переписку владельца этой сессии.

- Источники: приватный файл `config/monitor_chats.txt` (один чат или ссылка на строку).
- Ключевые слова: приватный файл `config/keywords.txt` (одно выражение на строку).
- Строки, начинающиеся с `#`, и пустые строки игнорируются.
- Оба файла перечитываются автоматически примерно раз в 10 секунд.
- Пропущенные во время обновления ассортимента события запрашиваются у Telegram
  примерно раз в 10 секунд и обрабатываются после освобождения соединения.
- Публичные чаты и invite-ссылки добавляются в аккаунт сессии автоматически.
- Текст, подпись, сведения об авторе, ссылка на оригинал и вложения отправляются
  от имени Bot API-бота.

Получатель определяется автоматически: это Telegram ID аккаунта, авторизованного
в `botAccount.session`. Перед использованием этот аккаунт должен открыть Bot API-бота
и нажать `/start`, иначе Telegram запретит боту отправлять личные сообщения.

`config/monitor_chats.txt`, `config/keywords.txt`, `.env`, Telegram-сессии и содержимое `data/` не
хранятся в Git. Docker Compose передаёт `.env`, список чатов и исходные файлы
сессий как read-only secrets в `/run/secrets`. Для SQLite-сессий создаются
приватные writable-копии в именованных Docker volumes.

## CI/CD на micro

Push в `main` запускает `.github/workflows/deploy-micro.yml`. Workflow по SSH
выбирает на сервере точный commit SHA и выполняет `docker compose up -d --build`.
Приватные файлы находятся только на сервере в `/opt/godmanagerbot/secrets`, а
runtime-данные — в `/opt/godmanagerbot/runtime/data`.

В GitHub Actions используются секреты `MICRO_HOST`, `MICRO_PORT`, `MICRO_USER`
и `MICRO_SSH_PRIVATE_KEY`. Ключ принадлежит отдельному пользователю деплоя и не
даёт root-доступ.

## Структура проекта

```
GMB2/
├── core/                    # Ядро приложения
│   ├── bot.py              # Главный класс бота
│   └── handlers/           # Обработчики событий
│       ├── order_handler.py      # Обработка заказов
│       └── assortment_handler.py # Управление ассортиментом
├── services/               # Внешние сервисы
│   ├── moy_sklad.py        # API Мой Склад
│   ├── telegram_client.py  # Telegram клиент (Telethon)
│   ├── google_sheets.py    # Google Sheets API
│   └── notifications.py    # Уведомления
├── utils/                  # Утилиты
│   ├── parsers.py          # Парсинг сообщений
│   ├── validators.py       # Валидация данных
│   └── auth.py             # Аутентификация
├── data/                   # Данные
│   ├── FinalAssortment.json    # Финальный ассортимент
│   ├── ItemNameHref.json       # Связи товаров
│   ├── AgentNameHref.json      # Связи агентов
│   └── FlavorDescriptions.json # Описания вкусов
└── config/                 # Конфигурация
    └── settings.py         # Настройки
```

## Установка

1. Клонируйте репозиторий
2. Установите зависимости: `pip install -r requirements.txt`
3. Cкачать в корневую папку файл `.env`
4. Запустите: `python main.py`

## Docker
Для запуска через докер нужно использовать короткие команды из файла commands.sh
./commands.sh rebuild

```bash
docker-compose up -d
```

## Команды бота

- `/start` - Запуск бота
- `/assortment` - Публикация ассортимента
- `/updateassortment` - Обновление ассортимента
- `/baseflavor` - Обновление описаний вкусов
- `/inventory` - Показать инвентарь
